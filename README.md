## Be Curveful: Omission of Wing Curvature in Pterosaur Flight Apparatus

This repository contains the full pipeline, metadata (both pterosaur wing outline and palaeoecological information) needed to run the analysis and reproduce the supplementary material.

## Structure
- `Msc_main_driver_v3.R` —  this script conducts the main analyses by sourcing the R codes composing the pipeline.
- `R/` — folder containing the codes covering wing outline extraction/loading, data handling, theoretical morphospaces, phylogenetics, and statistical analyses (PERMANOVA, allometry, disparity, EFA, PGLS, etc.).
- `data/` — the only raw inputs required to run the pipeline:
  - `pteros_main_data.csv` — the csv file containing all the palaeobiological, geomorphological and temporal information of the specimens used in this study.
  - `Pterosaur_Outlines_Clean.nts` — pre-extracted wing outline coordinates (used by `Msc_outline_02_load.R`; regenerate from raw silhouette images with `Msc_outline_01_extract.R` if required).
  - `phylogenetics/Henry` — base reference phylogenetic tree (NEXUS), used by `Msc_data_01_tree_creation.R` to build the modified tree for this study.
- `output/` — everything generated by running `Msc_main_driver_v3.R`: `pca_loadings.csv`, `phylogenetics/Henry_updated.tre`/`.nex` (grafted tree), and `results/`, `plots/`, `plots_PDF/` produced by the statistical/plotting modules. This folder makes the distinction between the files created by the pipeline and input files.
- `supplementals/` — supplemental tables/material assembled for the manuscript/thesis.

Raw wing silhouette images used for outline extraction are not tracked in this repository (large binary assets); place them under `data/pteros_out_finale/` locally to re-run extraction from scratch, otherwise the pipeline uses the pre-extracted outlines in `data/Pterosaur_Outlines_Clean.nts`.

## Usage

1. Download the repository.
2. Open `Msc_main_driver_v3.R` in RStudio.
3. Run the script — it will source all modules in `R/` in the correct order, read its required inputs from `data/`, and write every generated result to `output/`.
